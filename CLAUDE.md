# Rahasya: notes for Claude Code

- **Spec:** `docs/SPEC.md` is the source of truth and wins over the PDFs in `Documentation/` (PRD, design document, build plan). When the spec changes, re-export the Claude Doc "Rahasya implementation spec for Claude Code" as Markdown over it.
- **Order (agreed 2026-10-05):** backend and database first, screen by screen; frontend (`apps/app`, `apps/admin`, `packages/crypto|api-client|tokens|ui|motion`) last. Per-screen status lives in `apps/api/README.md`; keep it current.
- **Spec rules:** build in task-list order; plaintext secrets, master passwords and keys never leave `packages/crypto` (never log, send or store them unencrypted); where the spec is silent, follow the nearest specified screen and leave a `TODO:` that states the open decision, never invent features.
- **Comments (user rule, 2026-10-05):** write for someone who has never seen the spec, PRD or mockups. Say what a file, function or page does in the user's journey and why, never a screen code (S2, A4), requirement id (FR-12), animation code or document reference. Skip comments that repeat the code; add them only where intent, a rule or a trap isn't obvious.
- **Numbers** live only in `packages/config`. Import them; never hard-code a rule.
- **API conventions:** bytes travel as standard padded base64; every blob is checked against the spec's ciphertext format (`IsCiphertext`); request bodies are never logged; vault writes take the per-user revision lock first (`nextRevision`) and stamp rows with it.
- **Tests:** `pnpm --filter @rahasya/api test` runs unit and e2e tests against `TEST_DATABASE_URL` (Jest needs `--experimental-vm-modules` for Prisma 7; the script sets it). Every endpoint ships with e2e coverage of its rules.
- **Database:** add a migration per screen with `pnpm --filter @rahasya/api db:migrate --name <screen>`; migrations stay backward compatible for one release.
- **Frontend:** Expo SDK 57 (Metro bundler; Android needs a development build because of native libsodium). Style with Tailwind class names via Uniwind; colours, fonts and radii come from `packages/tokens` (edit the TypeScript, then `pnpm --filter @rahasya/tokens build`). Routes in `apps/app/src/app/` only render screens from `src/features/<journey>/`. Build test-first with React Native Testing Library 14 (its APIs are async). pnpm uses `nodeLinker: hoisted` so React Native exists once; don't change it.
- **Deploying:** `docs/DEPLOYMENT.md` (Render API from `render.yaml`, Neon Postgres, Vercel web from `apps/app/vercel.json`, EAS Android from `apps/app/eas.json`). `main` deploys to staging, `release` to production; CI (`.github/workflows/ci.yml`) must stay green.
